# GitHub, Vercel и Supabase

Облачная версия: Vite/React на Vercel, Supabase Auth (email + пароль) и приватная таблица проектов. Локальный сервер и прежние файлы остаются доступными через `npm run dev` без облачных переменных.

## Supabase

1. В проекте `rqxgvyhhtoodrnfkyfte` откройте SQL Editor и выполните `supabase/migrations/202609300001_projects.sql`. Миграция создаёт отдельную таблицу `home_planer_projects`, не изменяя другие таблицы.
2. В Authentication включите Email provider. По умолчанию подтверждение почты остаётся включённым. Добавьте адрес приложения Vercel в Site URL и Redirect URLs. Для локальной проверки добавьте `http://localhost:3000`.
3. В Project Settings → API Keys скопируйте **Publishable key** (допускается старый `anon` key). URL: `https://rqxgvyhhtoodrnfkyfte.supabase.co`.

Ключи `service_role`, `sb_secret_*` и пароль базы не нужны приложению и не должны попадать в Git или переменные `VITE_*`. Ограничение владельца обеспечивается RLS и серверной функцией, использующей `auth.uid()`. Клиент не имеет прямого разрешения на запись таблицы.

Сохранение одной транзакцией проверяет ревизию, увеличивает её и помещает предыдущий документ в `previous_document`. Одновременные первые сохранения также сериализуются. Конфликт возвращается в интерфейс с выбором отдельной копии или серверной версии. Геометрия и связи проверяются клиентом при сохранении и открытии; SQL дополнительно проверяет общую структуру и размер документа, но не повторяет весь геометрический решатель.

## Vercel

Импортируйте `onecheporenko99/home_planer` в команду `home-builder`. Настройки находятся в `vercel.json`: Vite, `npm run build`, каталог `dist`, `npm ci`.

Перед первым полноценным деплоем задайте переменные для Production и Preview:

```text
VITE_STORAGE_MODE=cloud
VITE_SUPABASE_URL=https://rqxgvyhhtoodrnfkyfte.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<публичный ключ проекта>
```

После изменения переменных запустите новый deployment: значения `VITE_*` встраиваются при сборке. Без конфигурации production показывает экран настройки, а не имитирует успешное сохранение.

## Локальная проверка облака

Скопируйте `.env.example` в `.env.local` и заполните публичный ключ. Перезапустите `npm run dev`, зарегистрируйтесь/войдите, создайте проект и сохраните его. `.env.local` исключён из Git. Удаление этого файла или `VITE_STORAGE_MODE=local` возвращает файловый режим.

Кэш восстановления разделён по ID пользователя. Выход сначала сохраняет изменения; при ошибке сохранения выход блокируется. Импорт старых локальных проектов выполняется явно: скачайте JSON в локальном режиме, импортируйте после входа в облачную версию и нажмите «Сохранить». Автоматической загрузки всех файлов `data/projects` нет.

## Проверка после публикации

- Создайте проект под первым аккаунтом, измените и сохраните, перезагрузите и откройте через «Открыть».
- Под вторым аккаунтом список должен быть пустым, а чтение чужого ID — недоступным.
- Откройте один проект на двух устройствах: второе сохранение старой ревизии должно вызвать конфликт.
- Проверьте восстановление трубы/прибора, слоёв и проёмов и вход по ссылке подтверждения email.
