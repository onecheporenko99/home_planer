## Переносимый архив

В редакторе: **«Архив с файлами» → «Скачать архив»**. На другом устройстве: **«Импорт ZIP / JSON»**, выбрать `.homeplaner.zip`, затем сохранить проект. При облачном режиме нужен вход: файлы загружаются в приватное хранилище текущего пользователя.

ZIP содержит `manifest.json`, `project.json` и `resources/<sha256>.bin`. Манифест v1 фиксирует формат, SHA проекта и список файлов. Папки, произвольные пути, ссылки и внешние URL не используются. Все ресурсы общей библиотеки текущего документа включаются, в том числе ресурсы неактивных этажей и вариантов. История прежних ревизий хранится отдельно и в ZIP не входит.

Лимиты: до 128 МБ для архива и распакованных данных, JSON до 5 МБ, до 200 ресурсов по 20 МБ, изображения до 8192 px / 24 Мп. Перед распаковкой проверяются каталог ZIP, количество/размеры, имена, дубликаты, шифрование, ссылки и пересечение диапазонов; распаковка использует только проверенные диапазоны и ограниченные выходные буферы. До загрузки файлов проверяются CRC, SHA, манифест, геометрия/ссылки проекта, сигнатуры и размеры ресурсов. Импорт создаёт новый ID и ревизию 0. Текущий проект открывается только после успешной загрузки всех ресурсов; ошибка не заменяет текущий документ. При сетевой ошибке уже загруженные неизменяемые файлы могут остаться в хранилище для повторной попытки.

JSON — только данные и ссылки. Его импорт с ресурсами разрешён, если все файлы уже доступны в текущем хранилище; иначе приложение предлагает полный ZIP. Старый JSON без ресурсов продолжает импортироваться.

Проверочный архив: `output/acceptance/phase2-example.homeplaner.zip` — три уровня, PDF-подложка и фото; восстановлен в пустом изолированном файловом хранилище. Локальный пример: **«Phase 2 — переносимый архив с файлами»**, ID `00988275-feb4-484b-a900-deed2f2ae34d`.

## Открытые пункты ручной приёмки

- Реальные клики новых панелей и импорта/экспорта ZIP в браузере. Повторная попытка доступа к `http://localhost:3003` отклонена инструментом из-за сохранённой настройки разрешений. Другие браузеры/адреса для обхода не использовались.
- Управление мышью и сенсорными жестами на физическом Windows/LAN-планшете. Логика жестов покрыта тестами; реальные устройства на этапе 10 не проверены.
- Вход, загрузка настоящих бинарных файлов и сохранение/повторное открытие Phase 2 через облачный интерфейс. SQL/PGlite не заменяет Supabase Auth/Storage по сети.
- Физическая печать: выбрать «100% / фактический размер» и измерить калибровочную линию 50 мм из `output/pdf/stage9-calibration.pdf`.

Эти пункты следует закрыть до окончательной ручной приёмки релиза. Дополнительный SQL для архива не нужен: используется уже проверенное приватное хранилище ресурсов и существующий RPC сохранения. Git push/Vercel deployment выполняются после отдельной команды пользователя.

## Повторение программных проверок

```powershell
npm test
$env:VITE_STORAGE_MODE='local'
npm run build
$env:VITE_STORAGE_MODE='cloud'
npm run build
node scripts/phase2-baseline.mjs
npm install --prefix tmp/sql-validation --no-audit --no-fund @electric-sql/pglite@0.5.8
node scripts/test-phase2-sql.mjs
node scripts/stage10-archive-example.mjs
```

Последний скрипт создаёт ZIP и проверяет пустое хранилище; без `--save-project` он не добавляет новый проект в пользовательский список. PGlite работает локально и не подключается к Supabase.
